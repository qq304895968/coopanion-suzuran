### 这些修改没有破坏哪些约定

- 十个扩展仍为 World API 6；保留原工具名、扩展入口、主要配置键与部署密钥读取方式。
- 旧 `pet-draw` / `coo-gen` 仍可独立安装，合并画室继续兼容旧数据目录；不建立运行时跨包相对导入。
- 日记依旧追加写入；日期、路径、普通文件和大小保护保留。
- 心情原子存储与屏幕/日记联动保留；新 installer 不替代运行时存储逻辑。
- QQ 外部内容标记和高影响操作的原有配置策略保留；新增测试不是授权扩大。
- 不删除 Arknights 离线资料、工作流、原始图片等必要资产。

## 二、全量检查中新发现并修复的问题

此前 QQ 没有有效的类型检查入口；真正启用后发现的不只是缺类型包。没有通过关闭 `strict` 或批量 `@ts-ignore` 来“修绿”。

| 问题 | 修复 / 证据 |
| --- | --- |
| Cortico 的 `node:module.registerHooks` 与旧 Node 类型声明不匹配 | Node 最低版本按 API 需要设为 22.15，`@types/node` 固定到 22.19.0；十包严格类型检查通过 |
| QQ 失效类型导入、logger 被声明为函数、未声明事件/消息段、错误的可空类型 | 与真实 SDK/模块接口对齐；补全 qzone/interact/sticker 协议类型；处理连接停止时的空 driver；保留旧宿主可选 `isPaused()` 的窄兼容层 |
| QQ 多个部署可能共享同一组可变默认子配置 | `qqDefaults` 和缺省补全使用独立深拷贝；对子配置原地合并，保留热更新引用；新增独立部署/畸形子对象测试 |
| 主动说话读取不存在的 `State.state`，并把对象传给地址参数 | 用已有 `firstMessageSent` 状态记录首次发言并转入稳定概率；用假时钟和持久化夹具回归 |
| QQ 空间 notice 先被通用 notice 分支截走 | 协议特定空间事件先分流，再处理普通 notice；保持外部事件边界，新增路由测试 |
| 提醒失败返回 `{ error }` 而不是宿主要求的 ToolOutcome | 返回 `{ text, failed: true }`；失败路径可被宿主正确解释，新增契约测试 |
| `Uint8Array.toString('hex')` 不能按 Buffer 方式使用；浏览器 SDK 参数不匹配 | 显式转换 Buffer 再检测签名；UI 使用 `ConfigValue`，按钮 tooltip 设在元素属性上 |
| 余额负数显示为 `$-1,234.50` | 改为 `-$1,234.50`；现有金额格式测试通过 |
| 余额密钥测试期待 `sk-[redacted]`，而实现更严格地抹掉整个已知 key | 保留更严格的脱敏，只修正测试对固定遮罩文本的错误假设，并断言完整 key 与后缀均不出现 |
| 日记装配测试使用 SDK 的默认时区却按 Shanghai 断言，某些时刻失败 | 测试显式固定部署时区，不修改生产日期语义 |
| 气泡补丁把“常量被引用”误判为“常量已定义”；过宽 `line.image` 标记会匹配 `line.images` | 改为精确的常量定义/淡出标记，并先在内存里验证全部补丁；禁止前半文件已经写入、后半锚点才报错 |
| 余额缺 README/CHANGELOG/自描述；四个包的 `describe.json` 与当前源码不一致 | 补齐余额文档与生成入口；通过 SDK 刷新 `coo-gen`、`coo-mood`、`emote-pics`、QQ 的元数据；新增十包 `check:metadata` 和显式 `describe:all` |

## 四、为什么没有“一次删完 / 全部重写”

1. **历史不重写**：取消跟踪后旧大文件仍存在于历史，正常 clone 仍可能较大。需要单独设计历史清理、备份和协作者迁移；本轮不 force-push。
2. **绘图不破坏独立安装**：物理镜像仍在，但现在有唯一维护来源、显式映射和 CI 防漂移。不是宣称磁盘上的重复已经消失。
3. **QQ 不冒险整体重构**：已隔离最需回归保护的三块职责并移除确定未调用的旧方法。收消息/ASR 生命周期等仍可继续拆，宜在真实宿主验收后进行。
4. **不碰真实部署**：安装器与 PowerShell 脚本的测试只使用临时夹具；默认均不应用。真实修改须你检查路径、停宿主并显式执行。
5. **不冒充已发布**：各包版本号未作为新发行版本发布；变更写在 `Unreleased`，没有推送、创建 PR 或发布 release。

## 五、维护者接手顺序

1. 阅读本清单和根 README，运行冻结安装与 `pnpm validate`。
2. 按人工验收文档在备份过的测试部署验收关键链路。
3. 审阅源码、文档和工作区状态；源码修改与新文件仍在本工作区。提交前用 `git status` / `git log` 核对实际状态，不假定前轮记录的本地 merge 仍是当前 HEAD。
4. 需要提交/推送或开 PR 时再明确执行；不要为了缩小旧历史直接强推 main。
5. 后续改共享绘图代码先改 `coo-draw` 并同步；改工具/事件/提示词后生成自描述再检查。
